# 10 — Interfície d'usuari i experiència

Disseny del frontend de la v2: sistema de disseny, navegació, patrons d'interacció i accessibilitat. Complementa l'stack tècnic de [03-arquitectura.md](03-arquitectura.md) §2.5 i els comportaments funcionals de [02-especificacio-funcional.md](02-especificacio-funcional.md).

## 1. Principis

1. **La UI és un client més de l'API**: cap lògica de negoci al frontend; el que la UI pot mostrar o fer ho dicta `GET /me/permissions` (la v1 deduïa permisos a cada pàgina amb `if rol == ...` duplicats i divergents).
2. **L'estat viu a la URL**: filtres, pàgina, ordenació i pestanyes com a query params (patró v1 que funciona bé i es generalitza a totes les pantalles) — el botó Enrere, els enllaços compartits i els marcadors sempre reprodueixen la vista exacta.
3. **Continuïtat visual amb la v1**: els usuaris ja coneixen l'aplicació. Es conserva l'estètica actual (fons clars, targetes translúcides, accents cel) formalitzada en un sistema de tokens — no es redissenya per redissenyar.
4. **Cap acció sense feedback**: tota operació mostra estat (carregant, èxit, error amb causa i acció correctiva), i les operacions llargues (sync, IA) mostren progrés real del job.

## 2. Sistema de disseny

- **Tokens de disseny** (CSS custom properties generades des d'un fitxer font): colors semàntics (`--surface`, `--ink`, `--muted`, `--accent`, `--success/warning/danger/info`), espaiat, radis, ombres, tipografia. Cap color literal als components.
- **Mode fosc real**: la v1 té el toggle però cap estil fosc; la v2 defineix els dos temes al nivell de token des del primer component. Detecció de `prefers-color-scheme` + preferència persistida per usuari.
- **Tipografia**: Inter (autoallotjada, no CDN) amb escala tipogràfica fixa; `tabular-nums` a totes les columnes numèriques i imports.
- **Biblioteca de components pròpia** (sobre Tailwind 4 + headless on calgui — Radix/Ark per a combobox, dialog, popover accessibles): `Button`, `Input`, `Select`, `Combobox` (cercadors d'empleat/contracte/grup Gestiona), `Badge` d'estat, `DataTable`, `Tabs`, `Modal`, `Toast`, `EmptyState`, `ProgressBar`, `StatCard`, `Timeline` (dates d'expedient), `DiffView` (comparativa de duplicats). Documentats amb Storybook o Ladle.
- **Un sol sistema de notificacions**: toasts + diàlegs de confirmació propis (la v1 barrejava SweetAlert2, `window.alert/confirm` i banners inline).
- **Formats regionals centralitzats**: utilitats úniques `formatCurrency`, `formatDate`, `formatDuration` (`ca-ES`) — la v1 les reimplementava a cada pàgina.

## 3. Navegació i estructura

- **Sidebar adaptativa** (com v1): les entrades depenen de mòduls actius (connectors/flags del servidor, servits en **una** crida — la v1 en feia 7 de seqüencials) i dels permisos efectius. Badge de pendents (duplicats) via un endpoint de resum únic.
- Zones: *Operativa* (Dashboard, Contractació, Adjudicataris, Favorits, Revisions, Duplicats), *Intel·ligència* (SuperBuscador, CPV, Auditoria, Pla, Generador documental), *Administració* (Configuració, Connectors, IA, Usuaris, Auditoria de seguretat).
- **Vista Admin/Usuari**: conmutable sense recàrrega de pàgina (la v1 feia `window.location.reload()`); és un paràmetre de consulta que el backend valida contra el rol real.
- Ruta 404 pròpia, rutes de creació explícites (`/contracts/new` — no col·lisions amb `:id` com a la v1), breadcrumbs a les fitxes.
- **Cerca global** (nou): un camp únic (Ctrl+K) que cerca expedients, menors, adjudicataris i pàgines.

## 5. Patrons d'interacció

- **Taules**: ordenació i paginació **server-side úniques** (la v1 duplicava client+servidor) amb total real; densitat configurable; columnes amb `tabular-nums`; selecció múltiple amb barra d'accions flotant (assignació massiva, export) — patró v1 conservat.
- **Filtres**: panell lateral/desplegable amb chips dels filtres actius i "netejar-ho tot"; debounce als camps de text; tot sincronitzat a la URL.
- **Jobs de llarga durada** (sync, enriquiment, exports, IA batch): llançament → toast amb enllaç → barra de progrés en viu (SSE de `/jobs/{id}/events`) → notificació final amb resum. Un component únic `JobProgress` substitueix els 4 fluxos SSE ad-hoc de la v1. Els jobs continuen si l'usuari navega; un indicador global mostra jobs actius.
- **IA**: sortides en streaming (redacció de seccions), sempre amb estat "esborrany" + accions explícites Acceptar/Rebutjar/Regenerar; les citacions de fonts del redactor són navegables; indicador de cost/model discret a cada resultat.
- **Formularis**: validació de client generada dels esquemes de l'API (mateixa font de veritat), errors al camp + resum; desada amb `PATCH` parcial i indicador de canvis sense desar.
- **Estats buits** dissenyats (primera sincronització, sense resultats, mòdul desactivat amb explicació i enllaç a configuració si ets admin).
- **Errors**: els `Problem Details` de l'API es mostren amb títol humà, detall i `trace_id` copiable per a suport.
- Confirmacions destructives amb el nom de l'objecte escrit o doble confirmació (fusions, eliminacions).

## 6. Accessibilitat (requisit legal)

Com a administració pública, el web ha de complir el **RD 1112/2018** (Directiva UE 2016/2102): **WCAG 2.1 nivell AA** és obligatori, no opcional.

- Navegació completa per teclat (focus visible, ordre lògic, skip links); components headless accessibles (rols ARIA correctes a taules, tabs, modals, comboboxes).
- Contrast AA a tots dos temes (validat als tokens, no component a component).
- Formularis amb etiquetes explícites i errors anunciats (`aria-live`); les barres de progrés i toasts anuncien canvis.
- `prefers-reduced-motion` respectat; textos redimensionables sense trencar el layout.
- Declaració d'accessibilitat publicada i auditoria (observatori d'accessibilitat) abans del tall.

## 7. Rendiment i qualitat

- Code splitting per ruta; llistats virtualitzats a partir de ~200 files; imatges i fonts autoallotjades.
- TanStack Query: cache per recurs amb invalidació per esdeveniments (una mutació invalida les consultes afectades); `getMe`/permisos/mòduls carregats **una vegada** per sessió.
- Pressupost: LCP < 2 s en xarxa municipal, bundle inicial < 300 kB gzip.
- Tests: unitats de components crítics (DataTable, filtres), tests E2E (Playwright) dels fluxos de [02-especificacio-funcional.md](02-especificacio-funcional.md) §2, i test d'accessibilitat automatitzat (axe) a CI.

## 8. Idioma

- UI 100% en català amb infraestructura i18n des del principi (claus de traducció, no strings incrustats) — permet castellà/aranès si mai cal sense reescriure.
- Codi, rutes i identificadors en anglès (coherent amb API i model de dades).
